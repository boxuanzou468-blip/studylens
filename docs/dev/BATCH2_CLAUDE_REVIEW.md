## 併入第三批修正

### 1. `learning_path` 可以引用 `skip` 段落（已重現）
在範例的 learning_path 裡加一筆指向 `label: "skip"` 的段落，`validate.py` 回報 0 個錯誤。「推薦學習路徑」裡出現「可跳過」的段落，本身就自相矛盾。

**改法**：
- learning_path 引用 skip 段落時，**列為錯誤**。
- learning_path 裡重複引用同一個段落時，也列為錯誤。
- topic_index 引用 skip 段落則允許，因為主題索引只是如實記錄某個主題出現在哪裡。

### 2. 整支影片標成一段也能通過（已重現）
把 240 秒的範例改成只有一段 0～240，`validate.py` 回報 0 個錯誤。真實情況下，AI 偷懶時很可能把一小時的影片切成三段交差，SPEC 要求的「1～5 分鐘一段」完全失效。

**改法**：新增**警告**等級，跟錯誤分開列，不影響退出碼。
- 單段超過 8 分鐘：警告。
- 單段短於 20 秒：警告。但 `skip` 段落、第一段和最後一段例外。
- 整支影片超過 10 分鐘卻只有 1 段：警告。
- 輸出格式改成 `PASS（2 個警告）`。SKILL.md 之後會要求 AI 在可行的情況下消除警告。

### 3. `chunk.py` 沒有告訴 AI 影片總時長
validate 要求最後一段的 `end` 等於 `duration_sec`，但 AI 讀區塊時只看得到 `[MM:SS]`，並不知道精確的時長，只能去翻 manifest。

**改法**：在 `chunk.py` 的標頭加一行：
```
時長 1234.567 秒（最後一段 end 請填此值）
```

### 4. 無語音影片的分析怎麼處理
無音軌或轉錄為空的影片沒有內容可以分析，但 library 校驗要求每支影片都要有分析，這樣永遠過不了。

**約定**（第 6 步寫進 SKILL.md，這批先在 examples 補一份範例並讓它通過校驗）：寫一份只有一段 `0 → duration_sec` 的分析。
- `label` 填 `skip`
- `reason` 填「無語音內容，無法判斷」
- `relevance` 填 0

## 第 5 步：HTML 報告的補充要求

SPEC 第四節照做。下面這些是 SPEC 沒寫清楚、但會直接影響能不能用的地方：

1. **產生報告前先校驗**：`build_report.py` 先在內部跑 profile、所有 analysis 和 library 的校驗，有錯誤就拒絕產生，並把錯誤列出來。
2. **安全嵌入資料**：
   - 標題、摘要這些文字都是 AI 寫的，可能含有 `<`、`</script>` 之類的字元。
   - 資料要放在 `<script type="application/json">` 裡，並把 `<` 跳脫成 `<`。
   - 前端只能用 `textContent` 渲染文字，**禁止用 `innerHTML` 拼接 AI 寫的文字**。
   - 測試要包含一筆標題是 `</script><img src=x onerror=alert(1)>` 的資料，確認不會被執行。
3. **影片路徑**：用相對於報告的路徑，每一層路徑都要 `encodeURIComponent`。中文、空格、`#`、`%` 都要能正常播放。
4. **瀏覽器播不了的格式**：mkv、avi、wmv、flv 這些格式 `<video>` 常常播不了，但 scan 會收進來。
   - 監聽 `error` 事件，播放失敗時在播放器的位置顯示提示：「瀏覽器無法播放此格式」，並附上檔案的相對路徑，提醒使用者可以用系統播放器打開，對照時間戳觀看。
   - 目錄和時間戳照常顯示。
5. **智慧播放的細節**：
   - 進入 `skip` 段時跳到段落結尾，並顯示 3 秒的提示：「已跳過：〈段落標題〉」，提示上有「回去看」按鈕。
   - 使用者手動拖到 skip 段落裡時，**不要再自動跳走**，尊重使用者的選擇，直到離開這一段為止。
   - 進入 `speed` 段時把播放速度設成段落的 `speed` 值，離開時恢復成使用者原本的速度，不是固定恢復成 1 倍速。
   - 開關狀態用 localStorage 記住，讀寫都要包在 try/catch 裡。
6. **標籤不能只靠顏色區分**：徽章上要有文字（重點／一般／加速／跳過），迷你時間軸滑過時要顯示 tooltip，方便色盲使用者辨識。
7. **網址錨點**：支援 `#v=<video_id>&t=<秒>`，開啟報告時直接跳到該影片的該時間點，方便分享筆記。
8. **測試素材**：
   - 用 examples 的資料產生一份報告，交回截圖，淺色和深色模式各一張，手機寬度一張。
   - 用 `studylens-測試素材` 的真實影片手寫一份小分析，實際驗證點擊跳轉和智慧播放。
   - 驗收方式可以用 Playwright 或其他工具，你自己決定，但要附上實際操作的證據。
