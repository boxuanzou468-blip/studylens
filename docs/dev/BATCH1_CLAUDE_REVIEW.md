## 必修（下一批先做）

### 1. 單一零長度段落會讓整支影片轉錄失敗
`normalize_segments` 遇到 `start == end` 會直接拋錯。faster-whisper 處理長影片時偶爾會產出零長度或時間倒退的段落，網路下載的 SRT 也常有零長度或重疊的字幕。結果是一支兩小時的影片可能轉錄完，卻因為一個「嗯」而整支作廢。

重現：
```python
normalize_segments([{'start':1.0,'end':1.0,'text':'嗯'}, {'start':1.0,'end':3.0,'text':'好'}], 10)
# → ValueError: 无效转录段落
```

**改法**：在 `normalize_segments` 裡容錯修正，不要失敗。
- 零長度段落：併入相鄰段落，或補到 0.1 秒；文字一定要保留。
- 開始時間倒退：夾到前一段的開始時間。
- 計數印一行警告（例如「修正 3 段異常時間」）。
- `check_segments` 維持嚴格，只用來驗證修正後的結果。
- 字幕超出影片時長超過 0.25 秒：沿用現在的報錯，這個合理。

### 2. 分塊時時間戳佔掉約 75% 的篇幅，浪費 AI 的 context
Whisper 的中文段落很短，每行前面卻都有 `[00:00:06.000 --> 00:00:09.000] ` 這段 32 字的時間戳。

實測：200 段典型字幕，每段約 11 字，6000 字的區塊裡真正的內容只佔 **25%**。等於 AI 要多讀 3 倍、多開 3 倍的區塊。後續分析的段落是 1～5 分鐘，精確到秒就夠了。

**改法**（`chunk.py`）：
- 時間戳格式改成 `[MM:SS]`，超過一小時才用 `[H:MM:SS]`，只標開始時間。
- 把相鄰段落合併成一行，約 20～30 秒一行，或遇到句末標點就換行。下一行的開始時間就是上一行的結束。
- 目標：內容佔比至少 80%。
- 6000 字的上限照舊。區塊目錄印出每塊的時間範圍，例如 `塊 1: 00:00–12:30`。

### 3. 轉錄進度每段印一行，會灌爆 AI 的 context
`consume()` 每完成一段就印一行。兩小時的課約有 1500 段，執行 skill 的 AI 讀輸出時會吃掉大量 context。

**改法**：每 5%、或每 30 秒才印一次，取兩者中較少的那個。開始和結束各印一行摘要。

## 建議一起修（成本低，對真實使用者影響大）

4. **預設開啟 `vad_filter=True`**，另加 `--no-vad` 可以關掉。真實課程常有長時間靜音，不開的話 Whisper 容易產生幻覺字串（例如重複句子、「字幕由 XX 提供」），開了也會比較快。
5. **重跑時參數略有不同，不該觸發整批重新轉錄。**
   - 把 `device` 和 `compute_type` 從 `cache_key` 拿掉，因為它們不改變結果的意義。
   - AI 重跑時很可能忘記加 `--language zh`。已完成的 whisper 逐字稿只要影片指紋沒變，預設就沿用，並印出「參數與上次不同，若要重做請加 --force」。
   - 最後一條規則：只有影片或字幕變動，才自動重做。
6. **字幕編碼自動偵測**：依序嘗試 `utf-8-sig` → `utf-16`（有 BOM 時）→ `gb18030`，全部失敗才報錯。`--subtitle-encoding` 保留作為強制指定。中文使用者下載的字幕很多是 GBK 編碼。
7. **模型下載失敗時的提示**：目標使用者以中文使用者為主，常連不上 Hugging Face。錯誤訊息和 `check_env.py` 都要提示，可以先設定 `HF_ENDPOINT=https://hf-mirror.com` 再重試，或用 `--model <本地資料夾>`。不要自動改成鏡像站，只做提示。
8. **Whisper 中文常輸出繁體或沒有標點**：加一個 `--initial-prompt` 參數，預設不帶。SKILL.md 之後會依使用者偏好的語言帶入，例如「以下是普通话的句子，使用简体中文和标点。」

## 可以延後（記錄在 README 的已知限制即可）
- `影片.zh.srt`、`影片.en.srt` 這類帶語言後綴的字幕（yt-dlp 的命名慣例）。第二版再支援，到時依 profile 的語言決定優先順序。
- mkv 內嵌的字幕軌。
- Windows 上的 GPU 執行庫：在 `check_env.py` 的提示裡附上 faster-whisper 官方說明的連結就好，不要自動安裝。

## 確認的資料約定（第 3 步照這些來）
- 第一批交接文件提出的 manifest 和 transcript 欄位**全部採用**，不用改。
- 第 3 步 `validate.py` 的規則：
  - 時間單位一律是秒（number）。
  - 第一段的 `start` 必須是 0。
  - 相鄰段落必須 `segments[i].end == segments[i+1].start`，容許 0.5 秒誤差。
  - 最後一段的 `end` 必須等於 `duration_sec`，容許 1 秒誤差。
  - `label` 只能是 `must`、`normal`、`speed`、`skip` 其中之一。
  - `speed` 只有在 label 是 `speed` 時才能出現，範圍 1.25～2.5。
  - `relevance` 是 0～100 的整數。
  - `library.json` 引用的 `video_id` 和段落索引都必須真的存在。
- **錯誤訊息要具體到 AI 能直接修正**，例如：
  > `segments[3].end (125.0) ≠ segments[4].start (130.0)：中間有 5 秒空隙，請延長 segments[3] 或提前 segments[4]`
- 每次執行都要列出**所有錯誤**，不要遇到第一個就停。
