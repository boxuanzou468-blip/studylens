## 第 6 步：`SKILL.md` 和 `AGENTS.md`（這是整個專案的核心，請寫得很具體）

`SKILL.md` 是使用者的 AI 唯一會讀的說明書，AI 拿到它要能從頭跑到尾，不需要回頭問開發者。必須涵蓋下面這些內容。

**A. Frontmatter**
- `name: studylens`。
- `description` 要中英雙語，寫清楚觸發情境。例如：「整理學習影片、影片目錄、哪段該看、課程太長、幫我挑重點、organize lecture videos」。

**B. 安裝與執行環境**
- 腳本路徑一律用「本 SKILL.md 所在資料夾」解析出的絕對路徑，不能假設目前的工作目錄。
- 第一次使用時，在 skill 資料夾裡建立 `.venv` 並安裝 requirements，之後都用這個 venv 的 Python。
- 依序寫出 Windows 和 macOS/Linux 的指令。
- 缺少套件時要直接安裝，裝好後告訴使用者，不要停下來問。
- 模型下載失敗時，照 `check_env.py` 的提示處理（鏡像站或本機模型）。

**C. 訪談**
- **一次問完**下面這些問題，不要一題一題來回問：
  - 影片資料夾
  - 學習目標（可以填多個）
  - 程度
  - 可選：時間預算、語言
- 使用者講得很模糊時（例如「我想學 Python」），追問一次，把目標縮小。之後就照答案寫 `profile.json`，跑 validate。
- 如果 `.studylens/` 裡已經有之前的結果，先問使用者：要沿用，還是依新目標重新分析？

**D. 掃描與轉錄**
- 轉錄放到背景執行，等待時只做簡短回報，例如「已完成 3/12 支」。
- 字幕優先。依使用者的語言帶入 `--initial-prompt`，例如簡體中文就用「以下是普通话的句子，使用简体中文和标点。」

**E. 逐支分析（品質要求寫清楚，這決定成品好不好用）**
- 一次只處理一支影片，用 `chunk.py` 逐塊讀完。讀完一支就寫出 analysis，跑 validate；有錯誤就修到通過，警告也要盡量消除。寫完就不要再留著這支的逐字稿內容。
- **可以續跑**：已經有 analysis 而且 validate 通過的影片要跳過。中斷後重新執行，從下一支接著做。
- **標題要具體**，要寫出這段講的東西：
  - ✓「用 for 迴圈走訪字典」
  - ✗「第二部分」「講解」
- **摘要要寫出內容本身**，不要寫「本段介紹了…」這種空話。逐字稿有明顯的語音辨識錯字時（例如同音字），在摘要裡改正，但不能編造逐字稿裡沒有的內容。
- **`reason` 要明確點出對應哪一個學習目標**，或為什麼和目標無關。
- **標註要校準**：
  - `must` 只給直接服務學習目標的段落，不能整支影片都標紅。
  - 依 profile 的程度判斷 `speed`：進階使用者聽到入門內容就標加速。
  - 開場寒暄、廣告、離題閒聊、重複內容標 `skip`。
  - 跟目標完全無關的影片，`relevance` 要低，標註以 skip 和 speed 為主。這是正常結果，不要硬湊重點。
- 無語音影片照第二批的約定處理：整支一段 skip。

**F. 彙整 library**
- 學習路徑的排序原則：
  - 先修知識排前面。
  - 以 `must` 段落為主，`normal` 段落只在銜接需要時才加入。
  - 有時間預算時，路徑的總時長不要超過預算。
- `stats` 直接用 `library_stats.py` 的輸出。

**G. 收尾**
- 跑 `build_report.py`，再幫使用者打開報告。
- 最後回報四件事：報告路徑、總時長、建議時長、省下的時間，再加上「最該先看的 3 段」。

**H. `AGENTS.md`**
- 簡短說明 repo 用途，告訴 Codex「執行任務時請完整依照 SKILL.md」。
- 補一段 Codex 的 skill 安裝方式。**請先查 Codex 目前的官方文件，確認 skills 目錄的位置**，不要憑印象寫。
