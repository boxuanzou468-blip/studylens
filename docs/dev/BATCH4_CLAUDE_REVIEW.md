## 第五批：發布前修正

### A. 分析品質（改 SKILL.md）
1. **摘要裡出現了流程說明**。Codex 那輪的摘要寫了「緩存逐字稿在 79 秒後沒有文字，未據此推測額外內容」，reason 也寫了「可節省 2 分鐘預算」（這個數字還不對）。使用者看到這些會覺得莫名其妙。
   - **改法**：在 SKILL 裡規定，summary 和 reason 只寫影片內容和它跟學習目標的關係。不能提到逐字稿、快取、字幕、預算計算這些工作過程。
2. **語音辨識的錯字沒有修正**。兩輪分析的摘要都沿用了「分布練習」，原文其實是「分步練習」。
   - **改法**：在 SKILL 的「糾正同音錯字」這條規則下，直接拿這個例子當示範。

### B. 校驗器
3. **短影片的「段落太短」警告不合理**。兩輪測試都卡在同一個 18 秒的警告上，原因是測試影片只有 85 秒，切成 4～5 個有意義的段落，本來就會短於 20 秒。
   - **改法**：影片總長不到 3 分鐘時，不發這個警告。
4. **警告重複，而且太長**。同一條警告在單支影片校驗和 library 校驗裡各印一次，每條都帶完整的絕對路徑，一條就超過 200 字。AI 讀這些輸出時很浪費 context。
   - **改法**：同一條警告只印一次；路徑改成相對於素材根目錄，例如 `analysis/7b33….json`。

### C. 報告介面（我的截圖：Claude Code 端 0:47 定位畫面）
5. **目錄依檔名排序**。相關度 20% 的「課程提綱」排在第 1 位，相關度 70% 的主課程反而排第 2。使用者最該看的影片應該排在最前面。
   - **改法**：預設依 `relevance` 由高到低排序，再提供一個「原始順序」的切換。
6. **播放器有兩套控制列**。原生 `controls` 和自訂的進度條、播放按鈕同時出現，畫面上有兩條進度條。
   - **改法**：保留自訂的那套，因為它有段落標記和基礎速度，然後移除原生 `controls`。但全螢幕和音量也要能用：自訂控制列要補上這兩個功能，或者只在全螢幕時開啟原生控制。
7. **右上角的「LOCAL LEARNING NOTES」是英文**，其他介面都是中文。改成中文或直接移除。介面多語系等第二版再做。

### D. 準備開源
8. **整理 repo 根目錄**：把 `SPEC.md` 和所有 `BATCH*_REVIEW.md` 移到 `docs/dev/`，README 底部加一行「開發紀錄」的連結。這些文件裡有本機路徑，例如 `<user>\...`：
   - 方案一：把本機路徑一律改寫成 `<repo>`、`<media>` 這類佔位符。
   - 方案二：不把這些文件放進 repo。
   - **選方案一**，因為開發紀錄本身就是這個專案很好的展示材料。
9. `tests/create_fixtures.ps1` 的預設輸出路徑是 `<local-path>`，改成必填參數，或預設成 repo 外一層的相對路徑。
10. **新增 `tests/README.md`**：說明哪些測試不需要任何外部條件；哪些需要 ffmpeg；哪些需要 Playwright 和 Chromium（用環境變數指定）；哪些需要 Whisper 模型。
11. **新增 GitHub Actions CI**：在 `ubuntu-latest`、`windows-latest`、`macos-latest` 上跑 Python 單元測試。
    - 安裝 ffmpeg，不下載 Whisper 模型，需要模型的測試要自動跳過。
    - 這樣不用花錢買設備，就能把 README 裡「macOS/Linux 未驗證」這條限制拿掉。CI 實際跑過哪些平台，README 就寫哪些，沒跑過的不要寫。
12. **README 補充**：
    - 已知限制裡加一條：用不支援 Range 請求的 HTTP 預覽伺服器開啟報告時，影片無法定位，請直接雙擊 HTML 檔案開啟。
    - 再加 CI 徽章。
13. **確認連結有效**：用 HTTP 請求檢查 README 和 AGENTS.md 裡的外部連結都能打開（特別是 OpenAI 技能文件的 `learn.chatgpt.com` 那個網址），把結果寫進交接文件。
